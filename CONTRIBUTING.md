# Contributing

Contributions should make the toolkit more accurate, safer, easier to use, or easier to verify.

## Before proposing a change
- Identify the asset and version affected.
- Explain the learner problem the change addresses.
- Include an example input and expected output when changing prompt behavior.
- Check that the change does not encourage fabricated experience or unsupported claims.
- Keep prompts bounded, with explicit inputs, outputs, and verification criteria.

## Prompt change checklist
- [ ] The task and target user are clear.
- [ ] Missing information is handled explicitly.
- [ ] Facts are separated from assumptions.
- [ ] Safety and privacy constraints are retained.
- [ ] The output format is specified.
- [ ] Acceptance criteria can be checked.
- [ ] Example outputs are labeled illustrative.
- [ ] `docs/CHANGELOG.md` is updated.

## Style
Use plain language, Markdown, and relative links. Avoid vendor-specific dependencies unless required. Prefer accessible, low-cost local lab options.
